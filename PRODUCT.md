# Sidework

Independent macOS-first AI browser, inspired by observed architectural behaviors, not copied Aside code/assets/private APIs. No source or binaries from the research directory may enter this repository or distribution.

Primary target workflow: normal browsing/search remains available without AI; from a new tab or task composer, describe an outcome → create goal-level work → agents create their own tabs inside the agent area → keep normal user tabs and input untouched → inspect results, steer, stop or take over. Existing-page attachment is optional. The goal-level bootstrap/decomposition runtime is not yet delivered; old existing-page transfer tests do not establish this target.

Product priority: a comfortable everyday browser with optional AI, not an agent dashboard containing webviews. Browser packaging is an implementation detail, not the product acceptance criterion. The user's latest browser-first correction supersedes demo-first priorities. See docs/BROWSER-FIRST-PRIORITIES.md for observed local gaps, public Aside feedback, proposed fixes and acceptance flows. Independent parallel AI remains unfinished under the user's strict acceptance target; coordinated-first-approval demos are not completion evidence.

User-approved visual direction: follow the observed Aside browser composition, superseding the historical Chrome-like/no-left-rail rule. Unified left sidebar for real task history and tabs, ordinary Tabs and Agent tabs distinct; compact top address/navigation row; central new-tab Search/Ask composer with secondary controls kept compact. Normal browser content remains primary, not a dashboard of cards. Preserve Korean readability and working controls. Never fabricate bookmarks, tasks, previews, capability readiness or success. Reference: docs/ASIDE-VISUAL-REFERENCE.md.

Provider: verified official local Codex CLI authentication path, controlled structured planning, no raw tokens/cookies in renderer. First-run model/network usage begins only after user requests a task; development smoke uses our harmless local fixture text.

Safety: app-owned persistent profiles; sandboxed remote pages without preload/Node; no access to personal Chrome profile. Typed actions only. Routine DOM actions on explicitly owned agent pages may execute automatically within their bounded main-owned capability. Consequential and unknown-risk actions still require exact confirmation; read-only denies mutation. Do not globally remove guards or widen permissions merely to enable a button. No arbitrary model JS/shell. Unknown post-mutation result is never auto-retried. Approval binds profile/tab/revision/action digest and expires. Memory explicit local opt-in, no analytics, sync or remote control.

Target acceptance: real Electron browser matches the approved Aside-led shell; actual sidebar/tab/search/task controls remain functional; a new-tab goal starts without user-created task pages, automatic pages stay in the agent area, independent child work and genuine outputs are verified, stale authority is rejected, and direct takeover preserves the exact page. Restarted work remains interrupted, not automatically resumed. Existing narrow 421-test/two-task fixture acceptance is lower-layer evidence only. Packaged arm64 macOS app must cold-launch from a relocated path. Unsigned/ad-hoc local distribution must be labeled.

Architecture scope: Electron is our initial shell, not an assertion of Aside's engine. Own Chromium fork, generic browser extension compatibility, OS Computer Use, Vault/passkeys and cloud sync remain separate work, not completed features. Track exact parity in docs/PARITY.md.
